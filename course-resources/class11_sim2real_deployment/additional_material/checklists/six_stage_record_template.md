# Six-stage final-project record

Keep the evolving record in the team project repository. Complete one worksheet during each class from Class12 to Class17. Submit the handwritten worksheet before the end of that class, signed by every team member. Later revisions are allowed; preserve the submitted version and date the revision. Use the course worksheet guide for its full definitions and evidence rubric.

|Class|Worksheet|Record|
|---|---|---|
|12|Claim|Proposed system, intended users/context, bounded claim, baseline and falsifiable test|
|13|Experience|Interaction episode, participant and system actions, intended experience, observable outcomes and alternative explanations|
|14|System|Embodiment, sensing, actuation, information flow, boundaries and assumptions|
|15|Grounding|Which physical/observational evidence supports each representation and claim; calibration, provenance and uncertainty|
|16|Learning|How data, adaptation or policy/model learning changes behaviour; splits, baselines, tests and failure evidence|
|17|Decision|What the evidence supports, remaining limits, next experiment and justified project decision|

A simulation project can make a supported simulation claim. Missing hardware evidence does not automatically invalidate that claim. Distinguish planned, observed and independently verified evidence. Do not replace worksheet evidence with a deployment ladder or assume all teams must execute hardware.

Classes18–20 prepare the poster, code and video. The assessed commit, results, dependencies and media belong in the team repository. Confirm deadlines against the current course schedule; this template does not establish new dates.
