# Class 03 student guide — B0 data collection and the Sim2Real gap

## What this class is about

This class uses the validated compact XC330 B0 model and a recorded physical experiment to show why a model can look plausible but still disagree with the real mechanism. The B0 moving assembly is the accepted 110 g fixture: a 22 g link and two complete 44 g pin–payload assemblies at ±60 mm. You work in simulation only: no motor, serial port, or phone is required.

You will compare:

- the position command sent during a V5 B0 experiment;
- the measured hardware joint position included in this project; and
- the same command replayed through an explicit saturated PD teaching controller in the validated B0 MuJoCo model before system identification.

## Setup

From this folder, run:

```bash
uv sync
uv run pytest
```

## Run the Class 03 activity

```bash
uv run python simulation_only/b0_data_collection.py
```

This command uses only local files. It opens a close MuJoCo view of the validated B0 fixture and a dashboard comparing the hardware measurement, MuJoCo response, residual, and current replay frame. It also creates:

- `outputs/b0_simulation_collection.csv` — paired simulated and measured positions;
- `outputs/b0_pre_identification_gap.png` — the comparison figure; and
- `outputs/b0_simulation_collection.json` — run summary including RMSE.

The physical trace is the embedded V5 B0/H2/P02 multisine episode, repeat R01. The cyan hardware curve is the included measurement and is not generated by this command. The replay loads `models/1DOF-B0.xml`, whose external moving mass is 110 g, joint range is ±π/2, collision is disabled, and actuator input is bounded at ±0.1551 N m.
The explicit simulation controller uses $K_p=2.5\ \mathrm{N\,m/rad}$ and $K_v=0.05\ \mathrm{N\,m\,s/rad}$. These declared gains have not been identified from the physical record and do not reproduce XC330 firmware.

## Questions to answer

1. Where are the measured and simulated positions furthest apart?
2. Does matching the geometry guarantee matching dynamics?
3. Name two effects not yet identified in this baseline model.
4. Why must we retain the measured trace instead of only showing a simulation plot?
5. Which model declarations are already supported by measurements, and which dynamic parameters still require identification?

## Explore the prepared fixture models

```bash
uv run python simulation_only/demo.py
uv run python simulation_only/activity.py --model B0 --payload-scale 1.25 --torque-nm 0.05 --duration-s 0.10
```

The second command retains the B0 geometry and applies the same torque pulse to two declared cases: the accepted 110 g fixture and a controlled hypothetical case in which both complete payload assemblies are 25% heavier, giving 132 g total external moving mass. Compare joint inertia, initial acceleration, final position, and final velocity in `outputs/b0_inertia_response_activity.json`. The 132 g result is a sensitivity experiment, not an as-built fixture claim.
Class 04 uses all 15 embedded V5 B0/H2 episodes: P01–P05 with repeats R01–R03. Repeats R01 and R02 provide 10 calibration episodes; R03 provides five independent validation episodes.

## Troubleshooting

If you do not have a graphical desktop, use `uv run python simulation_only/b0_data_collection.py --no-viewer --no-dashboard`. This verification mode writes the numeric CSV and JSON but no dashboard PNG.
